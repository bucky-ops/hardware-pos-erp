     1→// MBUMAH HARDWARE POS & ERP - Prisma Schema
     2→// Multi-tenant via storeId discriminator. PostgreSQL for prod, SQLite for dev.
     3→//
     4→// The committed provider is "postgresql" (for Vercel production).
     5→// For local dev with SQLite, `scripts/setup-prisma-provider.mjs` runs in
     6→// `postinstall` and detects the DATABASE_URL scheme:
     7→//   • file:./...        → switches to sqlite      (local dev)
     8→//   • postgresql://...  → stays postgresql         (Vercel / Neon / Supabase)
     9→//   • unset             → stays postgresql         (Vercel install phase)
    10→//
    11→// The `vercel-build` script runs `setup-prisma-provider.mjs && prisma generate`
    12→// before `next build` to ensure the correct client is generated even when
    13→// Vercel caches node_modules and skips the postinstall hook.
    14→//
    15→// Notes:
    16→//   - IDs use cuid() for cross-DB compat
    17→//   - Monetary fields use Decimal (banker's rounding)
    18→//   - Quantity fields use Decimal; rates
    19→//   - Hours/days fields use Decimal for payroll precision
    20→//   - JSON metadata stored as String; switch to Json type on PostgreSQL
    21→
    22→generator client {
    23→  provider = "prisma-client-js"
    24→}
    25→
    26→datasource db {
    27→  // Committed as "postgresql" for Vercel. Auto-switched to "sqlite" by
    28→  // scripts/setup-prisma-provider.mjs during postinstall when DATABASE_URL
    29→  // starts with "file:" (local dev). Do not edit manually.
    30→  provider  = "sqlite"
    31→  url       = env("DATABASE_URL")
    32→  directUrl = env("DIRECT_URL")
    33→}

  1315→// ─────────────────────────────────────────────────────────────────────────────
  1316→// PAYROLL & HUMAN RESOURCES (Phase 1 — ERP Enhancement)
  1317→// ─────────────────────────────────────────────────────────────────────────────
  1318→//
  1319→// Design notes:
  1320→//
  1321→//   • Multi-tenancy: Every store-scoped model carries a non-nullable `storeId`
  1322→//     and is registered in `STORE_SCOPED_MODELS` in src/lib/db.ts so the Prisma
  1323→//     Client Extension automatically AND-injects `storeId` into every query.
  1324→//     This enforces zero-trust tenant isolation at the ORM layer — developers
  1325→//     cannot "forget" to scope a payroll query by store.
  1326→//
  1327→//   • LeaveType is the ONLY model here WITHOUT a storeId. Leave types are
  1328→//     organisation-wide policy (Annual, Sick, Maternity, Compassionate, etc.)
  1329→//     defined once and referenced by every store. EmployeeLeaveBalance,
  1330→//     LeaveRequest, etc. resolve via employee.storeId.
  1331→//
  1332→//   • Monetary fields now use Decimal (banker's rounding)
  1333→//     across the entire schema — Product.pricePerUnit, SalesTransaction.total,
  1334→//     PayrollDetail.netPay, etc. This Phase 2 migration ensures KRA eTIMS
  1335→//     compliance and eliminates IEEE-754 float rounding errors. Payroll
  1336→//     fields (basicSalary, grossPay, paye, nssf, nhif, etc.) follow the
  1337→//     same convention.
  1338→//
  1339→//   • PAYSLIP immutability: PayrollDetail is append-only (a payslip, once
  1340→//     generated, must never be silently edited — corrections are made via
  1341→//     adjusting entries in the next payroll run). PayrollDetail is registered
  1342→//     in IMMUTABLE_MODELS in src/lib/db.ts; sanctioned mutations (e.g. voiding
  1343→//     a payslip) use withImmutabilityBypass().
  1344→//
  1345→//   • Status enums are stored as String (not Prisma enum) for SQLite/dev
  1346→//     compatibility and to allow adding new statuses without a migration.
  1347→//     The allowed values are documented inline and enforced at the API layer.
  1348→//
  1349→//   • PAYE/NSSF/NHDF: Kenyan statutory deductions are calculated in
  1350→//     src/lib/payroll-helpers.ts (Phase 2). The schema stores the FINAL
  1351→//     computed amounts; the breakdown is preserved in the `deductionsBreakdown`
  1352→//     JSON column for auditability and payslip rendering.
  1353→// ─────────────────────────────────────────────────────────────────────────────
